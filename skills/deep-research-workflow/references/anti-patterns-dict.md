# DR Anti-Patterns Dictionary v1.0

> 用于 Phase 1 prompt 生成（注入到 `known_context.anti_patterns`）和 Phase 2.5 critic 审查（命中即扣分）。
> 双向使用：生成时让 Gemini 主动避开，审查时机械检测命中数。

---

## Tier 1：禁用修饰词（命中扣 1 分/个，>5 个 / 千字 触发改写）

形容词类（去掉后语义不变 = 空话）：
- 工业化的 / industrial-grade
- 强有力的 / robust / strong
- 全方位的 / comprehensive / 360°
- 深度的 / 深层次的 / deep（除非后接量化数字，如"深度 ≥3 层"）
- 根本性的 / fundamental（除非用于哲学/数学定义）
- 体系化的 / systematic
- 战略级的 / strategic-level
- 颠覆性的 / disruptive
- 革命性的 / revolutionary
- 划时代的 / epoch-making

动词类（动作不可验证 = 空话）：
- 穿行（"在 X 与 Y 中穿行"）
- 跃迁（"从 X 跃迁到 Y"）
- 着力 / 致力于
- 赋能 empower（除非具体到工具/接口）
- 助力 / 拥抱
- 沉淀（除非后接具体产物）
- 锻造 / 打磨
- 重塑 / 重构（除非伴随具体方案）

修饰短语类（不变量 = 噪音）：
- 一定的 / 较好的 / 较为...
- 在...的同时...也... / 兼顾...的同时...
- ...为核心的 / ...为导向的（除非后接具体指标）
- 多维度的 / 全维度的
- 综合性的 / 立体的

## Tier 2：可执行性陷阱（命中即 reject，必须返工）

通用空话：
- "做好质量管控"（不说怎么做 → 必须给具体 SOP / 检查点）
- "建立差异化优势"（不说差异化什么 → 必须列 ≥3 条具体差异点）
- "持续学习迭代"（任何项目都能填）
- "提升用户体验"（不说什么 metric → 必须给 NPS/留存率/CSAT）
- "加强 X 与 Y 的协同"（动作不可验证）
- "优化 X 流程"（不说优化哪一步）

战略空话：
- "建立护城河"（不说护城河类型 → 必须明确：流量/数据/网络效应/规模效应）
- "形成正向循环"（不说反馈环路如何闭合）
- "占领心智"（不说怎么测量心智占有）
- "做大做强"（万能填空）

执行空话：
- "推动落地"（不说责任人 + 时间 + 验收）
- "保持高度警觉"（动作不可观测）
- "灵活应对"（无规则 = 无规则）

## Tier 3：数据陷阱（命中即 reject，必须返工或人工补来源）

数据规则：
- 表格中出现 `[推测]` 标签 → reject（推测数字不应表格化呈现，应转为定性描述或标 `[行业未公开基准，需自测]`）
- 数字精确到小数位但无 `[N]` 引用 → reject（除非紧邻有来源）
- "据估计/据说/通常认为/普遍认为/业内人士透露" 开头 → 必须有 `[N]` 否则 reject
- 同一来源在引用清单中出现 ≥3 次但其他来源 <2 次 → reject（单源充数）
- 同一域名贡献 ≥40% 引用数 → reject（来源集中度过高）

来源规则：
- 任何核心结论必须 ≥2 个独立域名 A/B 级来源支撑
- 任何"市场规模 X 亿"类数字必须有具体测算口径（不是直接引用别人的总量）
- 任何"X% 用户" 类比例必须含调研样本量 N
- 任何具体人名 + 具体数字组合（如"张三 SCC 收费 4000 美元"）必须有 ≥1 个 A/B 级来源
- 任何工具/产品/案例必须含官网 URL，缺失则标 `[URL 待补]` 而非伪造

时效规则：
- 引用 `vertexaisearch.cloud.google.com/grounding-api-redirect` 类间接链接 → 必须标"⚠️ 来源 URL 不透明"
- 核心结论支撑来源 >50% 来自 ≥2 年前 → 标"⚠️ 时效性风险"
- "2025 年趋势"/"2026 年预测"等前瞻性表述无近期来源 → reject

## Tier 4：跨报告协作陷阱（多 markets 并发时）

仅在 ≥2 个 markets 时检测：
- 同一概念在不同报告中定义不一致 → 在 Phase 2.4 midpoint 标记
- 同一数字（如 TAM）在不同报告中数值不同 → 必须在 Phase 2.5 给出"采用哪个 + 理由"
- 涉及"X 是否合理" 类二元判断的 Q，prompt 必须强制 "需考虑 [关联因素]" 列举所有相关 Q
- 多个 Q 共同结论必须由单一 Q 收敛输出，避免每份报告各说各话

## 命中后处理流程

| 命中等级 | 处理 |
|---------|------|
| Tier 1 单个 | ack，Phase 2.7 outline refinement 时批量替换为具体数字/动作 |
| Tier 1 密度 >5/千字 | Phase 2.5 critic 标记，要求 Gemini 改写整段 |
| Tier 2 任一 | 必须返工 prompt 或 Phase 2.7 人工改写 |
| Tier 3 任一 | 必须返工 prompt 或人工补来源；Phase 2.6 cross-validation 优先验证 |
| Tier 4 任一 | Phase 2.4 midpoint 注入"已发现冲突 X"到后续 prompt |

## 自动检测命令（Phase 2.5 自动运行）

```bash
# Tier 1 修饰词扫描（每千字命中数）
grep -oE '工业化|强有力|全方位|根本性|体系化|战略级|颠覆性|革命性|穿行|跃迁|赋能|沉淀|重塑' raw.md | wc -l

# Tier 3 数据陷阱扫描
grep -E '\[推测\]|据估计|据说|通常认为|业内人士透露' raw.md
grep -oE 'vertexaisearch\.cloud\.google\.com' raw.md | wc -l
```

完整版：`scripts/validate-anti-patterns.ts`（P3 实施）

## 词典维护

新增触发词时遵循：
1. 至少 3 次实战中遇到才入典
2. 必须给出"为什么是空话"的 1 句解释
3. 必须配 1 个"如何改写"的反例
4. 维护责任：每次 lessons-learned 沉淀时检查是否需扩词典
